# Pre-submission review (2026-11-19)

A review of `vignette("weighting-methods")`, the package source in `R/`, the roxygen documentation, NEWS.md, and the README before submitting 2.1.0.9003 to CRAN. Small fixes were applied directly and are listed under *Fixed*. Everything else is under *For you to decide*, roughly in order of importance. Neither `R CMD check` nor the full test suite has been run. The test files covering the changed code were run (see the end).

Bugs that were present in 2.1.0 (checked against `6d91526`, the last commit at that version) got NEWS items. The `method = "bart"` offset fix did not, since that code is new this cycle.

## `vignette("weighting-methods")`

Every claim about what a method supports was checked against `.weightit_methods` and the method's help page. Every citation key resolves in `references.bib`, and the flowchart's text agrees with the prose.

Fixed:

- **Naimi et al. (2014).** The continuous-treatment paragraph said they "found [the $t$-density] to perform better when the treatment has heavy tails." Their Discussion reports little difference between the $t$ and normal densities after truncation; they proposed the $t$ to limit the influence of outlying treatment values. The sentence now says that.
- **M-estimation exceptions for `method = "glm"`.** The paragraph said M-estimation is unavailable "with the Firth-corrected links," which reads as including the `br.` links (also Firth's). It now names `link = "flic"` or `"flac"`. It also adds the missing exception for a `multi.method` other than `"weightit"` or `"glm"`.
- **Estimands of the machine learning methods.** The section said all three "can target all the estimands available to `method = "glm"`". GBM does not allow the ATOS; the summary table already had this right.
- **Multi-category treatments in "Choosing a Weighting Method".** The old sentence said IPT and CFD don't allow the ATC there. For multi-category treatments, `weightit()` turns the ATC into the ATT with the control level as focal, so every method that allows the ATT also allows the ATC. Only nonparametric CBPS is restricted (ATE only). Energy balancing was the one exception: it failed with an error because of a bug, now fixed (see below). The sentence now says all methods are available and gives the npcbps restriction.

## Fixed in `R/` (all re-verified after the change)

Bugs:

- `weightit()` passed `estimand = "ATC"` unconverted to the method for multi-category treatments (`R/weightit.R`), where `weightit.fit()` passes the converted `"ATT"`. Energy balancing errored as a result. glm, ebal, cbps, ipt, optweight, and cfd give the same weights before and after the change.
- `.process_missing()` failed with a user-defined `method` and missing covariates.
- In `.process_by()`, the check that each `by` group contains every treatment level never fired for factors, because `nunique()` counts levels. It now uses `length(unique())`; `droplevels()` would fail on a numeric binary treatment.
- `weightit.fit()` did not translate method aliases (`"ps"`, `"GLM"`), which then failed downstream.
- `.get_w_from_ps_internal_array()` (binary, `stabilize = TRUE`) stabilized only the first column of the weight matrix. Final weights were unaffected, since only the gbm candidate matrix has more than one column.
- The four "probably a bug" messages in `weightit.fit()` interpolated `.bug_report_url` instead of calling it, so the message itself errored.
- `w.quantile()` with `na.rm = TRUE` used the length from before removing `NA`s. No current caller sets `na.rm = TRUE`.
- `weightitMSM()` printed one "method:" line per deparsed line of an anonymous function (`deparse1()` now).
- `weightit2ps.cont()` passed the full-length `ps` as `mu` with `by`.
- `weightit2glm.multi()` (`multi.method = "glm"`): the error handler's argument was `w` but its body used `e`.
- ebal rescaled `s.weights` by the mean including zero weights while `N` excluded them (binary, multi-category, and continuous). This scaled the weights wrongly and broke the M-estimation equations. The `.cens` version already did it right.
- `link = "flic"`/`"flac"`: `names(...get("modctrl_fun"))` should have been `names(...get("modcontrol"))`.
- `multi.method = "mnp"` silently ignored `s.weights`. Supplying them is now an error, as the docs already said.
- gbm, binary treatment not coded 0/1, ATT/ATC with `focal`: `bal.init()` got the 0/1 treatment with the original focal label and errored. For binary treatments it now gets `focal = NULL`, and the 0/1 coding with the estimand settles the focal group. Weights match the 0/1-coded fit exactly.
- gbm with a cross-validation `criterion` and several tuning values: `tree.val` was set only when a combination improved on the best, so later combinations reused earlier CV curves.
- `method = "bart"`: a user-supplied `offset` was not subset by `subset` (new this cycle, so no NEWS item). The error for a family that does not take sampling weights also no longer always names `dpm()`.
- `weightit2super.multi()` never set `cvControl$stratifyCV <- TRUE`, though the `@note` says multi-category fits stratify. This changes results for multi-category SuperLearner fits.
- `summary.weightit()`: `top` padded with `NA` when a group had fewer than `top` units; `digits` was ignored for the weight statistics table; and the text box plot drew a group with identical weights two characters too far right.
- `anova()` for `ordinal_weightit()` fits dropped the first covariate (`colnames(X1)[-1L]`, though `model.matrix()` has no intercept there). The statistic now matches the Wald test for `treat`.
- `multinom_weightit()` ignored `link`; anything but `"logit"` is now an error.
- `ordinal_weightit()`: an intercept-only model failed in `.get_hess_ordinal()` (`sds` undefined). The ascending-threshold check on `start` also used `ncol(x)` instead of the unaliased columns.
- `anova.multinom_weightit()`: removed a dead check that read `vcov_type` as an attribute, which it never is.
- `get.covs.matrix.for.dist()`: `.assign` was undefined with zero covariates. This is latent; `weightit()` never reaches it.

## Second pass (2026-11-19, after your answers)

- **`w.quantile()`.** The quantile terms balance a smoothed indicator, `plogis(2000 * (x - q))`, so a cutpoint that falls exactly on a data value gives that unit half credit, and a cutpoint between two values splits the units cleanly. The weighted type 2 rule fits that. It inverts the weighted empirical CDF; when `p` falls in a flat region of the CDF (e.g., the median of an even number of equally weighted units), it takes the midpoint of the region, so exactly a proportion `p` of the target lies below the cutpoint. Otherwise it takes the value where the CDF crosses `p`, which no cutpoint can split exactly. This was the original intent of the code: `>` should have been `>=`. The rewrite also aggregates tied values before forming the CDF, takes the flat region up to the next value with positive weight, and compares with a tolerance rather than `==`. It matches `quantile(type = 2)` exactly without weights and `quantile(rep(x, w), type = 2)` with integer weights.
- **`lambda` history.** Up to 1.4.0, every energy branch added `lambda / n^2` to the diagonal. In 1.5.0 (`51b18fb`, with `tols`), the binary branch changed to `lambda * (s_i / n_g)^2 / 2`, which puts the sampling weights into the penalty and normalizes by group size (and added the convex shift for a negative `lambda`). In 1.7.0 (`5cc7f50`), the multi-category branch got the same form, but the continuous branch became `lambda * s_i^2 / 2`, dropping the division by `n^2`. That is $n^2/2$ times the old penalty, which looks like an oversight in porting, since nothing else in that commit concerns `lambda`. CFD, added in `038c974`, copied the newer form for binary treatments and the older one for multi-category treatments. All branches now use the newer form, which is the only one that accounts for sampling weights. With unit sampling weights it differs from the pre-1.5.0 penalty only by a constant factor. The continuous lalonde example now gives an ESS of 278.19 at the default against 278.18 with `lambda` essentially 0, as the docs promise.
- **`subset`.** The legitimate use is a subgroup effect with weights estimated in the full sample. M-estimation could handle it (the outcome model's estimating functions are 0 outside the subgroup while the weighting model's are not), but fitting the model in the full sample with a treatment-by-subgroup interaction and using *marginaleffects* with `by` or `newdata` gives the same thing with machinery that already works. So `subset` is an error with `weightit` or `weights` and allowed without weights, where it already worked as in `glm()`.
- **Zero-weight units with missing covariates.** `.fill_nzw_model()` re-applies `.na_zero_weight()`'s donor-row fill to the stored model frame before every recomputation of the model matrix or response. That gives the same placeholders used in the fit, while `model.frame()` still reports the data as supplied.
- **Multinomial offsets.** Offsets are now an error, including an `offset()` term in the formula, which had worked and was tested; those two test blocks now expect the error. A sensible multinomial offset would be a matrix with a column per non-reference category, which nothing here supports.
- **`vcov`.** `vcov` is a string everywhere, including `anova()`, which had accepted functions and matrices. `.process_vcov_summary()` and `is.cov_like()` were dead and are removed. With `vcov` unset, only `cluster`, `R`, or `fwb.args` trigger a recomputation, and it uses the fit's own type and its stored `R` and `fwb.args`.
- **`calibrate()`.** `calibrate()` gains a `treated` argument (as in `get_w_from_ps()`) and resolves the treated level the same way; `calibrate.weightit()` uses the level recorded by `weightit()`.
